SECTION 2: COMPLETE TECHNOLOGY STACK (WHAT & WHY)
================================================================================

--------------------------------------------------------------------------------
A. BACKEND TECHNOLOGIES (100% DEPTH)
--------------------------------------------------------------------------------

1. Java 21 (LTS)
   - WHAT IT IS: The core programming language for all microservices.
   - WHY WE CHOSE IT: Offers long-term support (LTS), modern features like Virtual Threads (Project Loom) for lightweight concurrency, Record types for clean immutable DTOs, Pattern Matching, and enterprise-grade performance & stability.

2. Spring Boot 3.3.x & Spring Cloud 2023
   - WHAT IT IS: The foundational framework for building cloud-native Java microservices.
   - WHY WE CHOSE IT: Accelerates production-grade development with embedded Web servers, auto-configuration, dependency injection, REST controllers, and seamless Spring Cloud ecosystem integration.

3. Spring Cloud Gateway (Port 8080)
   - WHAT IT IS: The unified single access point for all incoming API traffic from the frontend.
   - WHY WE CHOSE IT: Decouples frontend clients from downstream microservice ports. Performs central JWT authentication filtering, CORS management, rate limiting, and injects user identity headers (`X-User-Id`, `X-User-Role`) to avoid redundant auth token verification in downstream services.

4. Netflix Eureka Discovery Server (Port 8761)
   - WHAT IT IS: A dynamic service registry and discovery engine.
   - WHY WE CHOSE IT: Eliminates hardcoded IP addresses or ports in microservice communications. Microservices dynamically auto-register and send health heartbeats. Enables dynamic load balancing and fault tolerance.

5. OpenFeign Client
   - WHAT IT IS: A declarative HTTP client for inter-microservice Remote Procedure Calls (RPC).
   - WHY WE CHOSE IT: Simplifies synchronous HTTP communications between microservices (e.g. Order Service calling Inventory Service) by turning Java interfaces into REST clients integrated with Eureka load balancing.

6. PostgreSQL 16 (Multi-Database Setup)
   - WHAT IT IS: Enterprise-grade Relational Database Management System (RDBMS).
   - WHY WE CHOSE IT: Provides full ACID compliance, strong relational data integrity, complex transactional support, and schema safety. Uses "Database-per-Microservice" architecture with 4 separate databases to enforce domain isolation.

7. Redis 7.x (Caching & Session Store)
   - WHAT IT IS: An in-memory key-value database used for caching hot data.
   - WHY WE CHOSE IT: Reduces database query latency to sub-milliseconds. Handles heavy read spikes during sales. 
     * Product Catalog cached for 5 mins (invalidated instantly on write).
     * Categories cached for 60 mins.
     * Flash Sales cached for 2 mins.

8. Apache Kafka & Zookeeper
   - WHAT IT IS: A distributed asynchronous event streaming platform.
   - WHY WE CHOSE IT: Decouples time-critical synchronous HTTP requests from background processing. Handles event-driven operations like sending email notifications and emitting analytics metrics without slowing down checkout.

9. JWT (JSON Web Token) + BCrypt Hashing
   - WHAT IT IS: Cryptographic stateless authentication mechanism paired with password hashing (strength 10).
   - WHY WE CHOSE IT: Ensures secure stateless sessions with a short 15-minute Access Token TTL and Refresh Token Rotation (RTR). Protects passwords against rainbow-table attacks.

10. Spring Data JPA & Hibernate
    - WHAT IT IS: Object-Relational Mapping (ORM) framework.
    - WHY WE CHOSE IT: Simplifies database persistence layer, converts Java entities to database tables, provides type-safe repository queries, and handles `@Transactional` boundary management.

11. Docker & Docker Compose
    - WHAT IT IS: Containerization engine and orchestration utility.
    - WHY WE CHOSE IT: Ensures identical execution environments across local developer machines and cloud deployment environments (Render/AWS). Manages container lifecycles for Java JARs, Postgres, Redis, and Kafka.

--------------------------------------------------------------------------------
B. FRONTEND TECHNOLOGIES (50% OVERVIEW FOR PRESENTATION)
--------------------------------------------------------------------------------

1. Next.js 16 (App Router) & React 19
   - WHAT IT IS: Full-stack React web framework utilizing server-side rendering (SSR) and dynamic client components.
   - WHY WE CHOSE IT: Offers optimal SEO performance for product pages, fast initial page loads, edge middleware routing, and seamless integration with modern React features.

2. TypeScript 5
   - WHAT IT IS: Strongly typed programming language built on JavaScript.
   - WHY WE CHOSE IT: Enforces strict type contracts between backend DTOs and frontend components, eliminating type mismatch errors during checkout and catalog rendering.

3. Tailwind CSS 4 & Radix UI / Shadcn UI
   - WHAT IT IS: Utility-first CSS styling framework combined with unstyled, accessible headless UI primitives.
   - WHY WE CHOSE IT: Enables rapid creation of a premium, glassmorphic visual aesthetic with dark-mode support, responsive layouts, and zero CSS bundle bloat.

4. Zustand & TanStack Query (React Query v5)
   - WHAT IT IS: State management pair — Zustand for client state, TanStack Query for server state.
   - WHY WE CHOSE IT: Keeps client-side shopping cart and user sessions lightweight (Zustand) while managing background fetching, response caching, and optimistic UI updates (TanStack Query).

5. Framer Motion & Lucide Icons
   - WHAT IT IS: React animation engine and vector icon collection.
   - WHY WE CHOSE IT: Adds dynamic micro-animations, interactive AI assistant drawer transitions, smooth hover states, and clean iconography.

SECTION 3: IN-DEPTH BACKEND MICROSERVICES BREAKDOWN (100% COVERAGE)
================================================================================

1. DISCOVERY SERVICE (`discovery-service` — Port 8761)
   - Tech: Spring Cloud Netflix Eureka Server.
   - Function: Central registry where all microservices register their host/port.
   - Key Value: Handles service discovery, heartbeat monitoring, and enables gateway/Feign client routing without hardcoded URLs.

2. GATEWAY SERVICE (`gateway-service` — Port 8080)
   - Tech: Spring Cloud Gateway, Reactive Netty Server.
   - Function: Main entry point for all frontend calls (`http://localhost:8080/api/v1/...`).
   - Key Features:
     * Validates JWT signature & expiry.
     * Extracts user ID and roles, injecting `X-User-Id` and `X-User-Role` headers downstream.
     * CORS policy enforcement and dynamic load-balanced request routing.

3. AUTHENTICATION SERVICE (`auth-service` — Port 8081)
   - Database: PostgreSQL (`nexmart_auth`).
   - Endpoints: `/register`, `/login`, `/refresh`, `/logout`, `/me`.
   - Security Highlights:
     * BCrypt password hashing (strength 10).
     * Short-lived Access Token (15 min TTL).
     * Refresh Token Rotation (RTR): Every refresh call revokes the existing refresh token and issues a brand-new token pair. If a revoked token is presented, all user sessions are terminated (Replay Attack Defense).

4. PRODUCT SERVICE (`product-service` — Port 8082)
   - Database: PostgreSQL (`nexmart_product`) + Redis Cache.
   - Endpoints: `/products`, `/products/flash-sales`, `/products/best-sellers`, `/categories`, `/:id/reviews`.
   - Caching Strategy: `@Cacheable` and `@CacheEvict` annotations store catalog data in Redis. Catalog queries return in <5ms. Automatically evicts cache on catalog updates.

5. ORDER SERVICE (`order-service` — Port 8083)
   - Database: PostgreSQL (`nexmart_order`).
   - Endpoints: `/checkout`, `/orders`, `/orders/:orderId`.
   - Logic: Computes 18% GST tax, shipping costs (₹99 for orders under ₹999; free above ₹999), and coupon validation (`NEXMART50`, `FREESHIP`). Orchestrates order states (`PENDING`, `RESERVED`, `PAID`, `FAILED`).

6. INVENTORY SERVICE (`inventory-service` — Port 8084)
   - Database: PostgreSQL (`nexmart_inventory`).
   - Endpoints: `/inventory/product/:id`, `/reserve`, `/confirm/:orderId`, `/release/:orderId`.
   - Concurrency & Locking: Uses atomic database row locking to reserve stock during checkout. Releases reservation automatically if payment fails or order times out (Saga Compensation pattern).

7. AI SERVICE (`ai-service` — Port 8085)
   - Endpoints: `/ai/assistant`, `/ai/pricing/dynamic`, `/ai/fraud/assess`.
   - Three Core AI Features:
     a. Semantic Search: Parses user intent (e.g. "shoes for running" -> maps to sports footwear catalog; fallback to best-sellers on no match).
     b. Dynamic Pricing Engine:
        - Low stock (< 10 units): Automatically increases base price by +8% (High Demand).
        - Excess stock (> 100 units): Automatically reduces base price by -5% (Inventory Liquidation).
     c. AI Fraud Risk Assessment: Scans order value and payment method. Orders exceeding ₹250,000 generate a high fraud score (0.88), blocking checkout until Two-Factor Authentication (2FA) is completed.

8. NOTIFICATION SERVICE (`notification-service` — Port 8086)
   - Function: Listens to Kafka order events and dispatches asynchronous order confirmations, delivery updates, and security alerts via mock email/SMS triggers.

9. ANALYTICS SERVICE (`analytics-service` — Port 8087)
   - Function: Aggregates real-time store metrics (gross revenue, active orders, total customers, daily sales velocity) for the Store Admin Dashboard.

10. COMMON DTO LIBRARY (`common-dto`)
    - Shared Library: Contains global Java DTOs (`AuthRequest`, `AuthResponse`, `UserDTO`), domain events (`OrderEvent`, `InventoryEvent`), and shared custom exception classes (`ResourceNotFoundException`).

- Slide Title: Enterprise Security Architecture
- Bullet Points:
  * Gateway JWT Filtering: Decodes JWT once and injects `X-User-Id` & `X-User-Role`.
  * BCrypt Hashing: Passwords encrypted with strength factor 10.
  * Short TTL Access Tokens: 15-minute expiration for minimal token exposure.
  * Refresh Token Rotation (RTR): New refresh token issued on every exchange; old token immediately invalidated.
  * Replay Defense: Using an invalidated refresh token revokes all user sessions.
- Speaker Notes: "Security is central to NexMart. Gateway validates JWT tokens statelessly and passes user identity downstream via custom headers. We enforce Refresh Token Rotation (RTR)—if an old refresh token is reused in a replay attempt, our auth service automatically revokes the entire token family."

SLIDE 6: HIGH-PERFORMANCE CATALOG & REDIS CACHING (PRODUCT-SERVICE)
- Slide Title: Product Service & Multi-Tier Caching
- Bullet Points:
  * Slug-based SEO URLs (`/products/gaming-laptop-v1`).
  * Spring Cache Integration: `@Cacheable` and `@CacheEvict`.
  * Tiered TTL Caching Strategy:
    - Products: Cached for 5 minutes (Evicted on stock/price edit).
    - Categories: Cached for 60 minutes.
    - Flash Sales: Cached for 2 minutes.
  * Database Load Reduction: 90%+ read queries hit Redis directly.
- Speaker Notes: "Product Service handles our catalog. To survive heavy traffic bursts during flash sales, we implemented a multi-tiered Redis caching layer. Catalog queries execute in under 5ms, protecting PostgreSQL from heavy read pressure."

SLIDE 7: SAGA ORCHESTRATION & CHECKOUT FLOW (ORDER & INVENTORY)
- Slide Title: Distributed Transactions & Order Saga
- Bullet Points:
  * Feign RPC: Synchronous order-to-inventory stock verification.
  * Step-by-Step Checkout Saga:
    1. Order Draft Created (Status: `PENDING`).
    2. Atomic Stock Reservation (Row-level pessimistic locking in Inventory DB).
    3. Payment Processing & Tax Math (18% GST + Shipping logic).
    4. Stock Commit -> Order marked `PAID`.
  * Compensating Rollback: On payment failure, inventory reservation is released immediately.
- Speaker Notes: "Because each service owns its database, standard SQL transactions won't work across Order and Inventory. We implemented a Saga Orchestration pattern using Feign clients and atomic row-locking to ensure stock is reserved safely and released if checkout fails."
